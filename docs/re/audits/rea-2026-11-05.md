# REA audit: what the public sites ship (2026-11-05)

Read-only audit of five public sites, done for the joint modern-web audit. Scope per site: the home page, up to 10 same-host pages linked from it, and the JS/CSS/wasm they reference. Every request was a plain anonymous `GET` or `HEAD` (User-Agent `Mozilla/5.0 (compatible; rea-audit/1.0; read-only)`, `Accept-Encoding: br, gzip`). No logins, forms, cookies or crawling beyond that. Downloaded files were kept as untrusted data in `var/audit-dl/<site>/` (gitignored) and never executed. The scanning scripts (`var/audit-scripts/rea-web.ts`, `inline-modules.ts`, `wasm-sections.ts`, `summarize.ts`) are local only and not committed.

Masking: any value that looks like a key or token is shown as its first 4 characters plus its length. Public tag IDs (GTM, AdSense) and Supabase project refs are masked too.

## Method notes and limits

- Static fetch only: the JS was not executed, so assets loaded only at runtime (lazy chunks, Next prefetches, studio sub-resources) are not counted beyond what the HTML or inline module scripts reference. Byte totals are lower bounds of what a browser downloads.
- "Wire" sizes are the compressed body lengths returned for `Accept-Encoding: br, gzip`. Every first-party text asset was served with `br`.
- Tracker and consent detection is string-based over the HTML, inline scripts and fetched bundles. A CMP configured server-side in Google's products (for example AdSense Funding Choices) would not be visible here.
- Secret scanning patterns: AWS, Stripe, OpenAI/Anthropic, GitHub, Slack, Google API keys, JWTs, PEM private keys, generic `api_key|secret|token=` assignments, Sentry DSNs, and Postgres/Redis URLs.
