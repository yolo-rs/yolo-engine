## 2. Linux KVM (Kernel-based Virtual Machine) Internals

KVM exposes virtualization capabilities through `/dev/kvm` ioctl primitives:

### 2.1 The KVM Execution Lifecycle
1. **VM Creation**:
   ```c
   int kvm_fd = open("/dev/kvm", O_RDWR | O_CLOEXEC);
   int vm_fd = ioctl(kvm_fd, KVM_CREATE_VM, 0);
   ```
2. **Memory Slot Allocation (`KVM_SET_USER_MEMORY_REGION`)**:
   Maps host user-space memory directly into guest physical address space (GPA -> HVA translation).
3. **vCPU Creation**:
   ```c
   int vcpu_fd = ioctl(vm_fd, KVM_CREATE_VCPU, vcpu_id);
   struct kvm_run *run = mmap(NULL, mmap_size, PROT_READ | PROT_WRITE, MAP_SHARED, vcpu_fd, 0);
   ```
4. **Execution Loop (`KVM_RUN`)**:
   Calling `ioctl(vcpu_fd, KVM_RUN, 0)` switches CPU context into guest non-root mode. Execution continues until a hardware VM-Exit occurs:
   - `KVM_EXIT_IO`: In/Out port I/O instruction.
   - `KVM_EXIT_MMIO`: Memory-mapped I/O access outside guest RAM.
   - `KVM_EXIT_HLT`: Guest halted (`hlt`).
   - `KVM_EXIT_INTR`: Host interrupt or signal interruption.

```
┌────────────────────────────────────────────────────────────────────────┐
│                        KVM vCPU Execution Loop                         │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
                                    ▼
                      ┌───────────────────────────┐
                      │  ioctl(vcpu_fd, KVM_RUN)  │
                      └─────────────┬─────────────┘
                                    │ (VM-Entry)
                                    ▼
                      ┌───────────────────────────┐
                      │ Guest Non-Root Execution  │
                      └─────────────┬─────────────┘
                                    │ (VM-Exit: MMIO, I/O, HLT)
                                    ▼
                      ┌───────────────────────────┐
                      │    Host User-Space Exit   │
                      │  Inspect `kvm_run->exit`  │
                      └─────────────┬─────────────┘
                                    │
                                    └────────────────────────┐
                                                             │
                         (Handle I/O or Virtio emulation)    │
                                                             │
                                    ┌────────────────────────┘
                                    ▼
                           [Loop to KVM_RUN]
```

## 3. Windows Hypervisor Platform (WHP / WinHv)

On Windows 10 and 11, the Windows Hypervisor Platform (`WinHvPlatform.dll` and `WinHvEmulation.dll`) permits third-party virtualization software (QEMU, VirtualBox, Docker Desktop, Android Emulator) to run concurrently with Microsoft Hyper-V, WSL 2, and Virtualization-Based Security (VBS / Credential Guard).

### Key WHP APIs:
- `WHvGetCapability`: Queries hardware hypervisor capabilities (EPT, dirty bits, nested paging).
- `WHvCreatePartition`: Creates hypervisor partition.
- `WHvMapGpaRange`: Maps host virtual memory to guest physical address space.
- `WHvCreateVirtualProcessor` & `WHvRunVirtualProcessor`: Drives guest vCPU threads and traps VM exits.

## 4. Apple Hypervisor.framework (HVF)

On macOS (both x86-64 and Apple Silicon M1-M4), `Hypervisor.framework` executes guest code in unprivileged user space without kernel extensions (`kexts`):
- Operates at ARM EL2 / Apple Silicon Hypervisor level.
- `hv_vcpu_create`: Initializes virtual CPU with designated target registers.
- `hv_vcpu_run`: Enters guest state.
- `hv_vcpu_set_reg` / `hv_vcpu_get_reg`: Directly updates general-purpose registers, system registers, and streaming vector states.

## 5. QEMU 9.x+ Architecture & Subsystems

QEMU 9.x provides hardware-assisted virtual machine acceleration and high-performance cross-architecture instruction translation.

### 5.1 TCG (Tiny Code Generator) & MTTCG
- **Frontend / Backend Intermediate Representation (IR)**:
  Target binary instructions (guest) are decoded into TCG micro-operations (IR), optimized, and compiled on the fly into host machine code.
- **MTTCG (Multi-Threaded TCG)**:
  Dedicated host OS threads drive each guest vCPU, leveraging atomic memory emulation (`TCG_MO_*` memory ordering) to safely emulate multiprocessor targets.
- **Translation Block (TB) Cache**:
  Cached native basic blocks linked directly to minimize JIT compilation overhead.

### 5.2 Virtio Virtual Device Architecture
Virtio defines standardized virtual device specifications over PCI or MMIO:
- **`virtio-net`**: High-performance paravirtualized network driver utilizing circular descriptors (`virtqueue`).
- **`virtio-block` / `virtio-scsi`**: Asynchronous ring-buffered disk I/O.
- **`virtio-fs`**: Shared file system passthrough utilizing FUSE and DAX (Direct Access) shared memory windows.
- **`virtio-gpu`**: 2D/3D hardware-accelerated rendering forwarding Vulkan/OpenGL commands to the host via Virglrenderer or Venus.
- **`vhost-user`**: Out-of-process device emulation in user space over UNIX domain sockets with zero-copy shared memory (`shm`), offloading heavy device drivers from the hypervisor process.

### 6.1 Apple Rosetta 2
- **Hybrid Translation Pipeline**:
  Performs Ahead-Of-Time (AOT) compilation during application installation into native ARM64 slices stored in `/var/db/oah/`. Uncompiled dynamic code or JIT falls back to an optimized runtime DBT.
- **Hardware Silicon Support (TSO Mode)**:
  Apple M-series chips include a hardware bit (`ACTLR_EL1.TSO`) that switches memory ordering from ARM Weak Memory Model to x86 Total Store Order (TSO), eliminating costly memory barrier instructions on every load/store.

### 6.2 FEX-Emu (Fast x86 Emulation for ARM64)
- Highly tuned for running x86-64 Windows and Linux games via Wine/Proton on 64-bit ARM Linux (Android, Steam Deck alternatives, ARM laptops).
- Directly uses ARMv8.4-A `LSE` atomics, `FLAGM` (condition flag manipulation), and hardware-accelerated thunks.

### 6.3 Box64 & Library Thunking
- **Concept of Thunking**:
  Instead of translating CPU instructions inside common libraries (such as `libGL.so`, `libvulkan.so`, `libc.so`, `libX11.so`), Box64 intercepts library calls and redirects them directly to the native host ARM64 libraries with argument marshalling.
- Achieves near-native GPU rendering performance in heavy 3D rendering and Steam gaming.

### 6.4 Unicorn 2 / Qiling / Frida
- **Unicorn 2 Engine**:
  Lightweight multi-architecture CPU emulator framework based on QEMU's TCG.
- Exposes fine-grained instrumentation:
  - `UC_HOOK_CODE`: Step-by-step instruction execution.
  - `UC_HOOK_MEM_READ` / `UC_HOOK_MEM_WRITE`: Memory access interceptors.
- Used extensively in reverse engineering, malware analysis, unpackers, and symbolic execution engines.
